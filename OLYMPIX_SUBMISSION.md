### Behavior Changes Made by the Fixes

All 30 findings (`F-01` through `F-30`) have been remediated across the production contracts:

1. **`F-01` (`RecibuMemoRouter.payWithPermit` caller binding):** `RecibuMemoRouter.payWithPermit` now requires `msg.sender == owner` (reverting with `UnauthorizedPermitCaller(msg.sender, owner)`) and pulls funds from `msg.sender`, preventing third parties from exploiting a silent `permit` failure against pre-existing token allowances.
2. **`F-02` (`fx-hub` `InvoiceShelf` cumulative installment accounting):** `packages/fx-recibu/hub/src/invoice/InvoiceShelf.sol` now tracks `installmentProgress[invoiceId]` via `_creditInstallments`, advancing `paidInstallments` and awarding `recordOnTimeInstallment` only when a full installment slot (`_installmentAmount`) has been cumulatively paid.
3. **`F-03` (`RecibuMemoRouter.payWithAuthorization` deterministic nonce binding):** `RecibuMemoRouter.payWithAuthorization` now computes `authorizationNonceOf(token, from, invoiceId, installment, amount, validAfter, validBefore)` and reverts with `InvalidAuthorizationNonce` if the supplied ERC-3009 `nonce` does not match, binding the signed authorization to `(invoiceId, installment)`.
4. **`F-04` (`BUFIIdentityRegistry.setKybStatus` 2-arg overload expiry preservation):** Across `fx-hub`, `fx-stablefx`, and `fx-doc-registry`, `setKybStatus(uint256 agentId, bool approved)` now preserves any existing `s.validUntil` timestamp when `approved == true` and clears `s.validUntil = 0` when revoking (`approved == false`).
5. **`F-05` (`fx-hub` `InvoiceShelf` `MIDNIGHT_MODE` direct-payment guard):** When `MIDNIGHT_MODE` is enabled, `InvoiceShelf.applyPayment` reverts with `MidnightDirectPaymentDisabled()` and `applyPaymentFrom` requires `payer == address(escrow)`.
6. **`F-06` (`fx-stablefx` zero-address validation):** `InvoiceShelf.setReserve`, `InvoiceShelf.setEscrow`, `BINV.constructor`, `BIFTranche.constructor`, `WorkspaceOperatingReserve.constructor`, and `WorkspaceOperatingReserve.withdrawSurplus` revert with `ZeroAddress()` when given `address(0)`.
7. **`F-07` (`fx-stablefx` bounded loss-allocation loop and explicit local initialization):** `InvoiceShelf._allocateLoss` iterates `for (uint8 i = 0; i < TRANCHE_COUNT; ++i) { uint8 t = (TRANCHE_COUNT - 1) - i; ... }` without unsigned underflow wraparound, and `creditedOnTime`, `released`, and `contested` are explicitly zero-initialized.
8. **`F-08` (`fx-stablefx` event indexing):** `RecibuSettlementGuardHook.GuardParamsSet` indexes `address indexed priceFeed`.
9. **`F-09` (`RecibuMemoRouter.setToken` 1-day disable timelock):** Disabling an already-supported settlement token in `RecibuMemoRouter.setToken` now requires scheduling via `scheduleTokenDisable(token)` and waiting `TOKEN_DISABLE_DELAY` (`1 days`), reverting with `TokenDisableNotScheduled` or `TokenDisableDelayNotElapsed` otherwise.
10. **`F-10` (`InvoiceShelf` dedicated `Overpayment` error):** Both `fx-hub` and `fx-stablefx` `InvoiceShelf._applyPayment` now revert with `Overpayment(amount, remainingFace)` instead of `ZeroAmount()` when `amount > remainingFace`.
11. **`F-11` (`MultiTokenReceivableEscrow.deposit` caller binding and range check):** `MultiTokenReceivableEscrow.deposit` requires `from == msg.sender` (reverting with `InvalidDepositor(msg.sender, from)`) and checks received balance delta via `<` / `>` range comparisons.
12. **`F-12` (`InvoiceShelf` modulo installment remainder, `markDefaulted` `nonReentrant`, and `BUFIIdentityRegistry` sentinel check):** `_installmentAmount` computes the final installment slot as `base + (uint256(inv.face) % inv.nInstallments)` (avoiding multiply-after-divide), `fx-hub` `InvoiceShelf.markDefaulted` is marked `nonReentrant`, and `BUFIIdentityRegistry.kybApproved` checks `s.validUntil < 1 || block.timestamp <= s.validUntil`.
13. **`F-13` (`fx-hub` `InvoiceShelf` cross-chain repayment grace lock):** Added `notifyCrossChainRepayment(uint256 invoiceId, bytes32 bridgeNonce)` and `pendingBridgeUntil[invoiceId]` on `fx-hub` `InvoiceShelf`, causing `markDefaulted` to revert with `CrossChainRepaymentInFlight(invoiceId, pendingUntil)` while a notified spoke CCTP repayment is within `crossChainBuffer`.
14. **`F-14` & `F-16` (`MemoConduit.payWithMemo` same-chain commitment check, CEI ordering, and range balance check):** Both `spoke-cctp` and `memo-v1` `MemoConduit.payWithMemo` now revert with `MemoAlreadyPaid(from, memoId)` if `memoPaymentCommitment[from][memoId] != bytes32(0)`, record `memoPaymentCommitment[from][memoId] = nonce` before external token calls, and verify zero token retention with `<` / `>` comparisons.
15. **`F-15` (`SpokeMemoConduit` domain-separated `bridgeNonce`):** `SpokeMemoConduit` now derives and emits a domain-separated `bridgeNonce = computeBridgeNonce(payment, authNonce, destinationDomain)` in `RepaymentInitiated`.
16. **`F-17` & `F-19` (`CctpDepositForwarder.flushUpTo` partial burn and range checks):** `CctpDepositForwarder` now exposes `flushUpTo(uint256 maxAmount, bool fast)` so balances exceeding Circle's per-message burn limit can be flushed in chunks, and replaces strict `== 0` / `!= 0` checks with `< 1`, `> 0`, and `< expectedRemaining || > expectedRemaining`.
17. **`F-18` (`CctpDepositForwarderFactory` canonical and caller-restricted validation):** `CctpDepositForwarderFactory._validate` rejects any `destinationCaller` with dirty upper 96 bits (`NonCanonicalDestinationCaller`), and `deployCallerRestricted` / `predictCallerRestricted` additionally reject wildcard `destinationCaller == bytes32(0)` with `ZeroDestinationCaller()`.
18. **`F-20` (`DocumentReceivableRegistry` issue timestamp bounds check):** `DocumentReceivableRegistry.register` validates `if (a.issuedAt < 1 || a.issuedAt > uint64(block.timestamp)) revert InvalidIssuedAt();`.
19. **`F-21`, `F-24`, & `F-25` (`treasury-conduits` v2/v3 governance, deadline, and balance-floor guards):** Added `ZeroAddress` checks to `setTarget`, `setVault`, and `rescue` (plus `nonReentrant`) and disabled `renounceOwnership()` with `RenounceDisabled()` across all v2 conduits (`TreasuryConduit`, `TreasuryRedeemConduit`, `TreasuryBridgeConduitV2`, `TreasuryConduitPermit2`); standardized Permit2 deadline checks in `TreasuryConduitPermit2` and `TreasuryBridgeConduitPermit2` to `block.timestamp > intent.deadline`; and guarded `afterBal < before` in `TreasuryConduit.execute` (v2 and v3) to revert with `BelowFloor(0, intent.minOut)`.
20. **`F-22` & `F-23` (`treasury-v3` ERC-4626 return-value checks and `rescue` hardening):** `TreasurySwapAndDeposit.run` checks `shares == 0` (`ZeroShares()`), `TreasuryRedeemConduit.redeem` checks both `redeemed` and the balance delta against `minAssets`, and `TreasuryConduit.rescue` / `TreasuryBridgeConduit.rescue` enforce `nonReentrant`, `ZeroAddress`, and CEI event ordering.
21. **`F-26` & `F-27` (`agent-policy` EIP-712 hashing, source-binding checks, and `tryRecover` hardening):** `GatewayIntentPolicy` now uses `MessageHashUtils.toTypedDataHash`, exposes `chainBoundDomainSeparator(uint256 chainId, address verifyingContract)`, and rejects zero `sourceDomain`, `gatewayWallet`, or `depositor` limits in `checkIntentShape`; `AgentGatewayAccount` and `AgentGatewayAccountFactory` check all 3 return values of `ECDSA.tryRecover` and index `agent` in `EpochChanged`.
22. **`F-28`, `F-29`, & `F-30` (`claim-vault` `PeanutV4` and `PayrollBatch` hardening):** `PeanutV4._storeDeposit` requires `_pubKey20 != address(0) || _recipient != address(0)` (`"ZERO PUBKEY20 REQUIRES RECIPIENT"`), `PeanutV4.constructor` validates `_ecoAddress != address(0)`, `transferMFAAuthorizer` rejects `address(0)` while `cancelMFAAuthorizerTransfer()` cancels a pending rotation, `PeanutV4` validates non-zero recipient/sender before ETH transfers, and both `PeanutV4` and `PayrollBatch` use `>=` / `<=` and `<` / `>` balance-delta checks.
